# Challenge 08 — Ionic React Maps

This implementation includes the requested examples **a, b, e and h**:

- **a. Network + current location:** reads connection status (Wi-Fi/mobile/offline), gets GPS coordinates, shows the map and reverse-geocodes the current address with OpenCage.
- **b. Movement detection:** optional automatic mode listens to the accelerometer. Movement starts route tracking; 15 seconds without significant movement stops it.
- **e. Vibration:** starting tracking triggers a short vibration using Capacitor Haptics.
- **h. Nearby search:** searches for a text category/name (for example `restaurant`, `pharmacy`, `cafe`) using OpenCage with the current coordinates as the proximity bias. Results are sorted by calculated distance and shown on the map.

The map tiles are provided by OpenStreetMap and rendered with Leaflet.

## 1. Install dependencies

Run these commands in the root of your existing Ionic React project:

```bash
npm install leaflet react-leaflet
npm install @capacitor/geolocation @capacitor/network @capacitor/motion @capacitor/haptics
npm install -D @types/leaflet
npx cap sync
```

**Capacitor version note:** the Capacitor plugins must use the same major version as `@capacitor/core` already installed in your project. If your project uses Capacitor 6, 7, or another major, install matching plugin major versions (for example `npm install @capacitor/geolocation@7 @capacitor/network@7 @capacitor/motion@7 @capacitor/haptics@7` for Capacitor 7). Check with `npm list @capacitor/core` first.

## 2. Add the files

Copy the `src/pages` folder and `src/App.tsx` into your project. If your project already has an `App.tsx`, this version assumes the standard Ionic React Router setup and can replace the empty starter router. Keep your existing `src/main.tsx` / `src/index.tsx` entry point.

If your project does not have `src/theme/variables.css`, keep the one generated by the Ionic starter or create it from the standard Ionic starter template. `App.tsx` imports it.

## 3. Configure OpenCage

1. Create a free/test API key at https://opencagedata.com/.
2. Copy `.env.example` to `.env` in the project root.
3. Replace the placeholder:

```env
VITE_OPENCAGE_API_KEY=YOUR_REAL_API_KEY
```

4. Restart Vite after editing `.env`:

```bash
npm run dev
```

Do not commit a real API key to a public repository. A key embedded in a frontend app can be inspected by users; for a classroom demo, restrict it in the OpenCage dashboard where possible.

## 4. Android permissions and testing

The Geolocation plugin requires location permissions. Check `android/app/src/main/AndroidManifest.xml` and ensure these entries are inside the top-level `<manifest>` element (not inside `<application>`):

```xml
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
```

Then build and sync:

```bash
npm run build
npx cap sync android
npx cap run android
```

On the Huawei phone:
- Turn on Location/GPS.
- Allow the app to access location.
- Enable Wi-Fi or mobile data for OpenCage address and nearby search.
- Tap **Enable movement detection** and grant sensor permission if requested.
- Walk or move the phone to start tracking; keep it still for about 15 seconds to stop it.

## 5. Important behaviour / limitations

- Wi-Fi is detected and displayed separately from general internet connectivity. GPS can still return a location without Wi-Fi; OpenCage address lookup and nearby search need internet.
- Movement detection is intended for foreground use while the app is open. It is not a background tracking service.
- OpenCage is a geocoding/search API, not a dedicated nearby-POI directory. Its proximity parameter biases text search toward the current location; it does not guarantee a complete list of all nearby businesses. For a production-grade “all places within 1 km” feature, use a dedicated POI source such as OpenStreetMap Overpass.
- The starter map is centered on Cali until the device's GPS location is obtained.
- OpenStreetMap tile usage is subject to its tile usage policy. Keep attribution visible.

## 6. Quick test checklist

1. Open the app and allow location permission.
2. Confirm the network chip displays `WIFI`, `CELLULAR`, or `OFFLINE`.
3. Confirm the map centers on the phone and the address appears.
4. Tap **Start**: the phone should vibrate and route tracking should begin.
5. Tap **Stop**: tracking should stop.
6. Enable movement detection, move the phone, and confirm tracking starts.
7. Leave the phone still for 15 seconds and confirm tracking stops.
8. Search `restaurant` or `pharmacy` and confirm results appear as list items and map markers.
